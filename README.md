# CoreDescriptionW2E

Офлайн-перенос русскоязычных описаний керна из DOC/DOCX в копию Excel-шаблона.
Без LLM, OCR, GPU, телеметрии, сетевых вызовов, Office и LibreOffice при обработке.

## Windows

Actions → успешный **Windows portable** → artifact `CoreDescriptionW2E-windows-x64`.
Распакуйте artifact, проверьте SHA-256 вложенного ZIP, распакуйте **весь** portable
ZIP и запустите `CoreDescriptionW2E.exe`. Python и Office устанавливать не нужно.
Выберите папку Word и XLSX-шаблон, нажмите **Заполнить**. Интерфейс работает во
время обработки; «Выход» ожидает её завершения. Статус и предупреждения — в окне.
Наличие workflow само по себе не означает готовности EXE: статус в [HANDOFF](docs/HANDOFF.md).

Каждый Word создаёт `<папка Word>/output/<stem>.xlsx`. Рекурсии нет; временные
`~$`-файлы исключаются. Существующие результаты GUI не заменяет: переместите их.
Одинаковые stem DOC/DOCX, включая регистр и Unicode, блокируют оба файла.
Ошибка одного Word не мешает остальным. Закройте заблокированный XLSX в Excel
и повторите обработку в пустую выходную папку.

## Разработка и CLI

Python 3.14, uv. Для Linux desktop нужны библиотеки Qt: на Ubuntu обычно
`libegl1`, `libgl1`, `libxcb-cursor0`; headless smoke использует `QT_QPA_PLATFORM=offscreen`.

```sh
uv sync --locked
uv run coredescriptionw2e --help
uv run coredescriptionw2e --input-dir data --template data/template.xlsx
uv run python -m coredescriptionw2e --input-dir data --template data/template.xlsx --output-dir data/check
uv run coredescriptionw2e-gui
uv run ruff check .
uv run ruff format --check .
uv run ty check
uv run pytest
```

`--overwrite` явно разрешает атомарную замену. Без него запрещена и конкурентная
перезапись. `--json` выводит сводку и причины отказов без текстов слоёв.
Exit codes: 0 — все книги созданы, возможны предупреждения; 1 — ошибки отдельных
Word; 2 — неверные аргументы/пути или отсутствие документов.
Portable EXE принимает `--cli` с batch-аргументами, но windowed EXE не имеет
консоли; для текстовой диагностики удобнее CLI из исходников.

## Форматы и правила

DOC: OLE/MS-DOC Word 97–2003, собственный ограниченный FIB/CLX/piece-table reader
с `olefile` 0.47. Внешнего декодера нет. Word 6/95, шифрование, поля бинарного
Word и текстовые рамки отклоняются. DOCX читается python-docx в XML-порядке,
включая вложенные таблицы; рамки, altChunk и отслеживаемые изменения отклоняются.
Основной текст сохраняется; сноски, колонтитулы, изображения и визуальное
оформление Word не импортируются. Макросы, ссылки и вложения не выполняются.
Лимиты: 64 МиБ файла/распакованного контейнера, 8 млн символов, 100 тыс. блоков.
Для неподдерживаемого документа нужна проверенная локальная копия DOCX без
рамок/исправлений. PDF не поддерживается.

Шаблон: 23 заголовка схемы `core23-v1` в [writer.py](src/coredescriptionw2e/excel/writer.py).
Перестановка столбцов допустима. Заголовок, стили и ширины сохраняются; старые
демонстрационные строки/инструкции заменяются слоями. Исходный шаблон неизменен.
G — относительный путь к Word обычной строкой; чужие метаданные не копируются.
Несовпадение номера скважины Word/примера диагностируется. Неизвестные поля пусты.

Decimal, допуск мощности 0,01 м. Слои не перенумеровываются, вынос не
приравнивается к проходке. Пласт берётся из предшествующего явного заголовка,
сохраняя его через границу долбления; пересечение глубин не служит основанием.
U — только однозначная начальная литология; V — буквальные предложения с
признаками УВ, включая отрицание. W — все блоки тела с переносами, начальной
мощностью и заключительной отметкой, если они присутствуют в источнике.
Слова с дефисом не склеиваются автоматически. Отсутствующее не дописывается.
Обратные/перекрывающиеся интервалы блокируют книгу; пропуски и неоднозначности
диагностируются. Предупреждения требуют проверки пользователя.

Формулы L/M пересчитывает Excel при открытии; openpyxl не вычисляет кеш.
Тексты сохраняются строками даже при начальном `=`. Превышение 32767 символов
в ячейке отклоняется без усечения. Публикация XLSX атомарная.

`data/` приватен, кроме пустого `.gitkeep`. Не загружайте документы, результаты,
локальные отчёты и скриншоты описаний в GitHub. Публичные fixtures синтетические.
[Архитектура](docs/ARCHITECTURE.md), [проверки](docs/TESTING.md), [сборка](docs/RELEASE.md).
