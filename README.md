# CoreDescriptionW2E

**[Скачать для Windows — GitHub Releases](https://github.com/GavrisAS/CoreDescriptionW2E/releases)**

Офлайн-перенос русскоязычных описаний керна из DOC/DOCX в копию Excel-шаблона.
Без LLM, OCR, GPU, телеметрии, сетевых вызовов, Office и LibreOffice при обработке.
Предварительные версии: визуальная и геологическая приёмка человеком остаётся PENDING.

## Windows

Скачайте portable ZIP и `.sha256` из одного Release, сверьте SHA-256 и распакуйте
**весь** ZIP в новую папку. Запустите `CoreDescriptionW2E.exe`; Python и Office
устанавливать не нужно. Выберите папку Word и XLSX-шаблон, нажмите **Заполнить**.
«Выход» ожидает завершения обработки. Таблица показывает каждый Word-кандидат,
его исход, причину и результат; двойной щелчок открывает книгу. Кнопка открытия
результатов также позволяет найти приватный batch JSON с census и диагностикой.

PASS создаёт `output/<stem>.xlsx`, REVIEW_REQUIRED — `output/review/<stem>.xlsx`.
Review-книга открывается на листе «Контроль»: русский статус, легенда, проблемы,
ID/интервалы и ссылки на строки. Обратные ссылки — в колонке источника основного
листа. «Реестр» показывает родителей/части, исходный % Word и итоги; «Источники»
сохраняет исходные блоки и карту разделения. Все эти файлы приватны.

Рекурсии нет. Каждый верхнеуровневый DOC/DOCX, независимо от регистра расширения,
имеет явный исход, включая исключённые Office `~$` и symlink. Точки/кириллица
в имени не исключают документ. XLSX и вложенные каталоги не считаются входами.
Существующая книга даёт `skipped: target_exists`; используйте новую выходную
папку. Одинаковые stem DOC/DOCX с учётом регистра/Unicode блокируют оба файла
с диагностикой. Ошибка одного Word не мешает остальным.

Каждая успешная production сборка `main` публикуется с уникальным patch `0.1.P`.
[Release и checksum](docs/RELEASE.md), [приватный handoff](docs/HANDOFF.md).

## CLI и разработка

Python 3.14, uv. Linux desktop обычно требует `libegl1`, `libgl1`,
`libxcb-cursor0`; headless smoke использует `QT_QPA_PLATFORM=offscreen`.

```sh
uv sync --locked
uv run coredescriptionw2e --help
uv run coredescriptionw2e --input-dir data --template data/template.xlsx --output-dir data/check
uv run coredescriptionw2e-gui
uv run ruff check .
uv run ruff format --check .
uv run ty check
uv run pytest
```

`--overwrite` явно разрешает атомарную замену. Без флага запрещена также
конкурентная перезапись. `--json` возвращает объект с `summary` и `results`.
Счётчики: `discovered / queued / converted_pass / converted_review /
unsupported / error / skipped_with_reason`. Сумма пяти конечных категорий равна
`discovered`; `queued` исключает только discovery skips. Уникальный локальный
`batch-*.json` дополнительно хранит полный census и приватную доменную модель.
Не публикуйте этот файл. Exit codes: 0 — все PASS; 3 — есть REVIEW_REQUIRED без
отказов; 1 — ERROR/UNSUPPORTED/skipped; 2 — неверные аргументы или отсутствие
кандидатов. Portable EXE принимает `--cli`; windowed EXE не имеет консоли.

## Бизнес-правила и схемы

Нормативные решения специалистов и явно отмеченные временные интерпретации —
[BUSINESS_RULES.md](docs/BUSINESS_RULES.md), включая таблицу всех 16 ответов.

- `LAYERED_DESCRIPTION`: исходные долбления и геологические слои. Пропущенные
  номера/неправильные интервалы не исправляются. Допустимое перекрытие даёт
  REVIEW_REQUIRED с подсветкой обеих строк; обратный порядок и ошибки ГИС
  остаются блокирующими.
- `CORE_INTERVAL`: родительские записи «Керн N» в физических двухъячеечных
  строках. Отдельные доказанные абзацы `Верх/Низ` или `число м — порода` могут
  стать дочерними строками. При неоднозначности описание остаётся целиком с
  `split_ambiguous`. M/N–Q/T частей пусты: мощности не превращаются в глубины
  или искусственные номера слоёв. Режим остаётся REVIEW_REQUIRED.
- J — только объявленная проходка; K — явный линейный вынос/л.в.к./вынос керна
  либо парное «Проходка …, керна …». **Коробки не штатный источник K**.
  Разные допустимые источники K конфликтуют. J<K сохраняется как review.
  L всегда формула K/J при известных K и положительном J. % Word — отдельно.
- Явный нулевой выход имеет голубую строку K=0 на основном листе без фиктивных
  слоя и W. Неизвестная J остаётся пустой. Бурение без отбора — только Контроль.
  Итоги считаются по уникальным родителям, а не повторяющимся дочерним строкам.
  Итоги Word не заменяют исходные значения; семантика/охват сверяются отдельно.
- Только доказанный полный дубль исключается из основных строк. Оба ID, тексты,
  поля сравнения, ссылка на оставленную запись и эффект на суммы сохраняются.
- U — однозначная начальная порода или короткая комбинация при явном
  переслаивании. V — исходный положительный признак нефти/углеводородов,
  включая слабый запах; отрицание не становится насыщенностью. R пусто без
  самостоятельной ГИС-привязки, S — однозначный пласт из Word.
- W сохраняет полный смысловой фрагмент с начальными/конечными числовыми
  отметками. Сомнительные дефисы и переносы не склеиваются; raw хранится отдельно.

Входной пользовательский шаблон остаётся **core23-v1: 23 заголовка A–W**.
Перестановка семантических колонок допустима. Исходный шаблон не изменяется,
заголовки/стили/ширины сохраняются, демонстрационные строки заменяются.
Выход **core24-v1** добавляет физический X «Номер скважины по описанию керна»:
точный идентификатор Word с исходным регистром/суффиксом, без вывода из имени
файла. D сохраняет прежний источник `metadata.well`; совпадение D и X допустимо.
G содержит относительную ссылку на Word и внутреннюю навигацию к контролю.

Decimal, допуск 0,01 м; сравнение процентов — 0,5 процентного пункта по умолчанию.
Неизвестные критические ошибки блокируют книгу по закрытой политике.
Текст записывается строкой даже при начальном `=`. Лимит ячейки 32767 символов
не обходится усечением. Высота W оценивается до максимума 409 pt; длинный текст
дополнительно доступен связанными фрагментами на листе «Описание».
Формулы L/M вычисляет Excel при открытии; openpyxl не вычисляет кеш.
Публикация XLSX — через временный файл и атомарное перемещение.

## Чтение и приватность

DOC: OLE/MS-DOC Word 97–2003, ограниченный собственный FIB/CLX/piece-table reader
с `olefile` 0.47, без внешнего декодера. Word 6/95, шифрование, поля бинарного
Word и содержательные текстовые рамки отклоняются. Пустые рамки допускаются
только после исчерпывающей проверки диапазона textbox-story и PlcftxbxTxt.
DOCX: python-docx, XML-порядок и вложенные таблицы; рамки, altChunk и исправления
отклоняются. Сноски, колонтитулы, изображения и визуальное оформление Word не
импортируются. Макросы/ссылки/вложения не выполняются. Лимиты: 64 МиБ файла/
распакованного контейнера, 8 млн символов, 100 тыс. блоков. PDF не поддерживается.
Неподдерживаемые структуры дают объяснимый UNSUPPORTED, без неполной книги.

`data/` приватен, кроме пустого `.gitkeep`. Не публикуйте входы, результаты,
диагностику, вопросник и скриншоты. Публичные fixtures синтетические.
[Архитектура](docs/ARCHITECTURE.md), [проверки](docs/TESTING.md),
[лицензирование](docs/THIRD_PARTY_NOTICES.md). Код MIT; Qt/PySide LGPLv3,
olefile BSD; portable содержит заменяемые DLL, лицензии и точные source bundles.
