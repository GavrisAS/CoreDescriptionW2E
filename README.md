# CoreDescriptionW2E

**[Скачать для Windows — GitHub Releases](https://github.com/GavrisAS/CoreDescriptionW2E/releases)**

Предварительные версии: машинные проверки обязательны; визуальная приёмка Excel пользователем ещё ожидается.

Офлайн-перенос русскоязычных описаний керна из DOC/DOCX в копию Excel-шаблона.
Без LLM, OCR, GPU, телеметрии, сетевых вызовов, Office и LibreOffice при обработке.

## Windows

В Releases скачайте portable ZIP и его `.sha256`, сверьте SHA-256 и распакуйте
**весь** ZIP в новую папку. Запустите `CoreDescriptionW2E.exe`; Python и Office
устанавливать не нужно. Выберите папку Word и XLSX-шаблон, нажмите **Заполнить**.
«Выход» ожидает завершения обработки; статус и предупреждения — в окне.
Каждая успешная production сборка `main` публикуется автоматически с уникальным
patch `0.1.P`. [Версионирование и checksum](docs/RELEASE.md),
[текущие проверяемые evidence и приватный handoff](docs/HANDOFF.md).

PASS создаёт `<папка Word>/output/<stem>.xlsx`; REVIEW_REQUIRED —
`<папка Word>/output/review/<stem>.xlsx`. Review-книга открывается на заметном
листе «Контроль», исходные конфликты сохраняются и требуют проверки. Рекурсии нет; временные
`~$`-файлы исключаются. Существующие результаты GUI не заменяет: переместите их.
Одинаковые stem DOC/DOCX, включая регистр и Unicode, блокируют оба файла.
Ошибка одного Word не мешает остальным. Закройте заблокированный XLSX в Excel
и повторите обработку в пустую выходную папку.

## Разработка и CLI

Python 3.14, uv. Для Linux desktop нужны библиотеки Qt: на Ubuntu обычно
`libegl1`, `libgl1`, `libxcb-cursor0`; headless smoke использует `QT_QPA_PLATFORM=offscreen`.

```sh
uv sync --locked
uv run coredescriptionw2e --help
uv run coredescriptionw2e --input-dir data --template data/template.xlsx
uv run python -m coredescriptionw2e --input-dir data --template data/template.xlsx --output-dir data/check
uv run coredescriptionw2e-gui
uv run ruff check .
uv run ruff format --check .
uv run ty check
uv run pytest
```

`--overwrite` явно разрешает атомарную замену. Без него запрещена и конкурентная
перезапись. `--json` выводит сводку и причины отказов без текстов слоёв.
Exit codes: 0 — структурный PASS всех файлов (возможны предупреждения);
3 — есть REVIEW_REQUIRED без ошибок файлов; 1 — есть ERROR/UNSUPPORTED;
2 — неверные аргументы/пути или отсутствие документов. JSON отдельно показывает
режим, итоговый статус, число записей и путь к книге. Ошибка записи Excel не даёт PASS.
Portable EXE принимает `--cli` с batch-аргументами, но windowed EXE не имеет
консоли; для текстовой диагностики удобнее CLI из исходников.

## Форматы и правила

DOC: OLE/MS-DOC Word 97–2003, собственный ограниченный FIB/CLX/piece-table reader
с `olefile` 0.47. Внешнего декодера нет. Word 6/95, шифрование, поля бинарного
Word и содержательные текстовые рамки отклоняются. Пустые рамки допускаются
только после проверки всего диапазона textbox-story и PlcftxbxTxt: каждый символ
должен быть знаком конца абзаца. Это ограниченный допуск, не общий импорт рамок. DOCX читается python-docx в XML-порядке,
включая вложенные таблицы; рамки, altChunk и отслеживаемые изменения отклоняются.
Основной текст сохраняется; сноски, колонтитулы, изображения и визуальное
оформление Word не импортируются. Макросы, ссылки и вложения не выполняются.
Лимиты: 64 МиБ файла/распакованного контейнера, 8 млн символов, 100 тыс. блоков.
Для неподдерживаемого документа нужна проверенная локальная копия DOCX без
рамок/исправлений. PDF не поддерживается.
Поддержаны два режима:

- `LAYERED_DESCRIPTION`: долбления и слои, включая строгий заголовок
  «Интервал N. A–Bм (C–Dм)». Ограниченный конфликт буровых интервалов может
  дать REVIEW_REQUIRED с подсветкой обеих затронутых строк. Обратный порядок,
  ГИС-перекрытия, отсутствие текста/границ/ID блокируют книгу.
- `CORE_INTERVAL`: физические двухъячеечные строки «Керн N»/«Керн № N»,
  собственные интервал, проходка, линейный вынос и полное описание в одной W.
  Одна исходная запись — одна строка. M, N–Q и T остаются пустыми; ID керна,
  исходный процент, метрики, SourceRef и интервалы без керна — на «Контроль».
  Литология/УВ составного керна пока не интерпретируются (U/V пусты, есть issue).
  Номера и дубли сохраняются. Этот режим всегда REVIEW_REQUIRED,
  с обозначением «НЕ ПОСЛОЙНО»; геологические глубины не реконструируются.

Неоднозначная таблица, смешанные семейства и потеря обязательных данных дают
UNSUPPORTED без XLSX. Неположительные продуктивные метрики дают ERROR.
Ошибки исходного процента, вынос выше 100% и несовпадение сводок
не блокируют полный CORE_INTERVAL, но остаются видимыми конфликтами.

Шаблон: 23 заголовка схемы `core23-v1` в [writer.py](src/coredescriptionw2e/excel/writer.py).
Перестановка столбцов допустима. Заголовок, стили и ширины сохраняются; старые
демонстрационные строки/инструкции заменяются слоями. Исходный шаблон неизменен.
G — относительный путь к Word обычной строкой; чужие метаданные не копируются.
Несовпадение номера скважины Word/примера диагностируется. Неизвестные поля пусты.

Decimal, допуск мощности 0,01 м. Слои не перенумеровываются, вынос не
приравнивается к проходке. Пласт берётся из предшествующего явного заголовка,
сохраняя его через границу долбления; пересечение глубин не служит основанием.
U — только однозначная начальная литология; V — буквальные предложения с
признаками УВ, включая отрицание. W — все блоки тела с переносами, начальной
мощностью и заключительной отметкой, если они присутствуют в источнике.
Слова с дефисом не склеиваются автоматически. Отсутствующее не дописывается.
Обратные и структурно неоднозначные интервалы блокируют книгу; разрешённые
конфликты исходника переводят её в REVIEW_REQUIRED по закрытому списку кодов. Предупреждения требуют проверки пользователя.

Формулы L/M пересчитывает Excel при открытии; openpyxl не вычисляет кеш.
Проходка J и линейный вынос K повторяются в каждой строке слоя своего долбления;
L ссылается на J/K той же строки. При отсутствии одного показателя L пуста,
достоверный второй показатель сохраняется. Перестановка колонок учитывается.
K: `в коробках` → явный линейный вынос/л.в.к./вынос керна → парное
«Проходка …, керна …». Отдельное `керна` не заполняет K. Значения каждого
источника сохраняются отдельно. Нулевой вынос разрешён только для явно пустого
долбления с `в коробках 0`, без фиктивного слоя. Проценты сравниваются с точным
настраиваемым в Python API порогом 0,5 процентного пункта по умолчанию.
Тексты сохраняются строками даже при начальном `=`. Превышение 32767 символов
в ячейке отклоняется без усечения. Высота строки оценивается по переносам
и ширине W с пределом Excel 409 pt. Если оценка выше предела, полный W остаётся
в ячейке, а лист «Описание» показывает связанные фрагменты для чтения. Полная
видимость произвольного текста в одной строке не гарантируется. Публикация XLSX атомарная.

локальные отчёты и скриншоты описаний в GitHub. Публичные fixtures синтетические.
