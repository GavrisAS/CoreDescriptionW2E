# Архитектура

`word` → `ImportedDocument` → структурный parser → validation → `excel.writer`.
GUI worker и CLI вызывают один `service.convert_batch`; сетевых операций нет.
Зависимости и packaging Python 3.14/uv/PySide6/openpyxl сохранены без добавления
библиотек или внешних декодеров.

## Исходник и происхождение

Raw text и `TextBlock.raw` отделены от нормализованного `text`. NFC и горизонтальные
пробелы нормализуются, числа, тире и абзацы не исправляются. `SourceRef` задаёт
файл, XML-путь/диапазон текста, порядок и физическую ячейку. DOCX читает реальные
`w:tr/w:tc`, без дублирования merged-cell proxies. Вложенные неоднозначные core
таблицы отклоняются по учёту всех заголовков. MS-DOC использует FIB/CLX/PlcPcd;
плоские двухъячеечные core-строки требуют cell marks и двойной границы строки.
Это ограниченная грамматика, не универсальная реконструкция DOC-таблиц.

Послойные описания в правой колонке могут продолжаться в следующей правой
ячейке. Текст соседних служебных колонок не присоединяется к W: он сохраняется
в импорте и на «Контроль» как ANCILLARY_SOURCE с SourceRef и диагностикой.
Неподтверждённые структуры не получают фиктивных слоёв.

## Две модели

`LAYERED_DESCRIPTION`: `CoringRun` → `Layer`, буровые/ГИС интервалы, исходный
номер слоя, полный W. Якоря: Долбление, Слой, строгий двухинтервальный заголовок
Интервал N, Пласт, Доюрский комплекс, Всего, подписи. После сводки текст не
попадает в W. Метаданные долбления берутся до первого слоя, не из описания.
Явная стратиграфия действует до следующего заголовка, включая границу долбления.

`CORE_INTERVAL`: `CoreInterval` содержит исходный ID, интервал отбора, явные
проходку, вынос, заявленный процент и описание из соседней физической ячейки.
Парсер в `core_parser.py`, валидатор `validate_core`, отдельны от послойной ветки.
Полнота требует учёта всех физических core-строк, известного ID, единственного
интервала, J/K и непустой W. Сводки и соседние записи в W не допускаются.
Составные Верх/Низ остаются единой W. U/V пока оставлены пустыми с issue:
геологическая интерпретация составного керна не является условием переноса.
`NoCoreInterval` различает NO_RECOVERY и DRILLED_WITHOUT_CORE. В основном
листе они отсутствуют, в контроле сохраняются интервал, тип и буквальный источник.

## Метрики и политика

`Metric` хранит Decimal, variant, SourceRef, DECLARED/COMPUTED и confidence
EXPLICIT/PAIRED/DERIVED. Варианты: declared_drilled, declared_core, boxed_core,
linear_recovery, declared_percent, computed_percent. J = явная проходка.
K: boxed_core → linear_recovery (включая л.в.к./вынос керна) → declared_core
только в парной шапке «Проходка …, керна …». Различные declared_core/boxed_core
не подменяют друг друга. Однотипные противоречащие метрики блокируют результат.
Из разницы глубин K/J не восстанавливаются. `в коробках 0` допускается для
доказанно пустого долбления; J всё равно должен быть положительным, если указан.

Для итогов послойного документа читается только двухъячеечная сводка с явным
«Всего по скважине» и «Всего поднято керна». Подытоги по пластам не складываются
с общим итогом. Отсутствующая метрика не заменяется сводкой; ограничение сверки
диагностируется. CORE_INTERVAL сверяет суммы всех записей, отдельную гипотезу
исключения кандидата на дубль, вариант с NO_RECOVERY и source_declared.
Ни один вариант диагностики не исключает строк из экспорта.

Режим и статус независимы. PASS означает структурный экспорт без известных
конфликтов, не ручную геологическую приёмку. CORE_INTERVAL всегда REVIEW_REQUIRED.
`ParseResult.exportable` допускает PASS/REVIEW_REQUIRED по `REVIEW_CODES` в
`validation.py`. Только закрытый список recoverable source conflicts может
пройти с severity=error. Любая неизвестная ошибка блокирует экспорт. Известные
parse_failure/reader_incomplete/invalid_xml/missing_text/ambiguous_boundaries/
missing_identifier/empty_body блокируют даже при ошибочно указанной warning.
ГИС-перекрытие, обратный порядок, повреждение структуры остаются блокирующими.
Категории: INVALID_SOURCE_DATA, UNSUPPORTED_STRUCTURE, READER_LIMITATION и
INTERPRETATION_LIMITATION. ERROR означает неэкспортируемый некорректный факт
или техническую ошибку; UNSUPPORTED — недоказанную структуру/полноту импорта.
Порог процентов задаётся `percent_tolerance` в parse/service Python API,
по умолчанию Decimal("0.5") процентного пункта. Округлённые исходные проценты
не заменяются вычисленными. Допуск интервалов/мощности 0,01 м не меняет числа.

## DOC и рамки

FIB задаёт длины всех stories; CLX/piece-table читается в CP-порядке, с проверкой
границ, монотонности, кодировок и размера. Основная story не сканируется по байтам.
Для ненулевого ccpTxbx/ccpHdrTxbx проверяется весь соответствующий диапазон,
PlcftxbxTxt/PlcfHdrtxbxTxt (FTXBXS 22 bytes, CP ranges), отсутствие полей.
Разрешён только диапазон, состоящий целиком из 0x0D, включая игнорируемый хвост.
Тогда содержательного текста рамок нет и порядок привязки не влияет на полноту W.
Текст, пробел, табуляция, anchor или неизвестная конструкция в рамках дают
unsupported_doc_textbox. Это строгий частный случай, не отключение старого gate.
Содержательные/связанные рамки требуют сопоставления FTXBXS.lid ↔ PlcfSpa и
проверки порядка stories; такая поддержка сейчас не заявляется. Независимое
локальное DOC→DOCX сравнение допускается только как dev oracle; LibreOffice
не поставляется и не вызывается приложением/Windows EXE/CI.

Спецификация Microsoft:

[PlcftxbxTxt](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/9f17f89a-64d6-4546-a811-e62e1d238102),
[FibRgFcLcb97](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/0c9df81f-98d0-454e-ad84-b612cd05b1a4),
[Retrieving Text](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/01d5d8c4-cf9c-4ef9-80fd-439e763cfe01),

## Excel

Входной шаблон проверяется как один лист core23-v1 с 23 семантическими заголовками.
Контроль добавляется после проверки. Переставленные колонки разрешены; стиль
шаблона сохраняется, J/K повторяются на всех слоях долбления, L = K/J текущей
строки с IFERROR и процентным форматом. Отсутствие K оставляет L пустой.
CORE_INTERVAL заполняет H/I, собственные J/K/L/W; M, N–Q, T пусты, ID на Контроль.
R/S не выводятся без явного источника. Review открывается на Контроль и не
смешивается с PASS; известные затронутые строки подсвечены, есть внутренние ссылки.

Тексты всех листов проходят set_text: тип s, запрет усечения/управляющих символов,
защита от формульной инъекции. Только внутренние ссылки на строки книги, G —
относительный путь, без внешних URL. Формулы пересчитывает Excel при открытии.
Высота строки консервативно оценивается по ширине W/переносам, максимум 409 pt.
При превышении весь W остаётся неизменным, а Описание содержит короткие связанные
фрагменты для чтения; визуальная полнота одной строки не гарантируется.

Временный XLSX в целевом каталоге → ZIP CRC → fsync → atomic publication.
Явная замена — os.replace; без замены Windows os.rename, POSIX os.link без clobber.
Старый файл и исходный шаблон при сбое сохраняются.
