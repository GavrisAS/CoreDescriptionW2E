# Правила разработки CoreDescriptionW2E

- Python 3.14, src-layout, uv и коммитируемый `uv.lock` после первого `uv lock`.
- Приложение полностью офлайн: без LLM, GPU, OCR, телеметрии, сетевых API и скачиваний во время пользовательской обработки.
- GUI и CLI используют один сервис конвертации. GUI: папка Word, Excel-шаблон, «Заполнить», «Выход», прогресс и итоговый статус.
- Принимаются `.doc` и `.docx` без установленного Microsoft Word; готовая Windows-сборка не должна требовать отдельных установок.
- Парсер отделяется от импорта документов, доменной модели, валидации и записи Excel. Нормализованный текст не заменяет исходную копию.
- Значения без достоверного источника не выдумывать. Конфликты и неоднозначности отмечать в отчёте; критические ошибки не скрывать.
- Не исправлять молча исходные интервалы, номера слоёв, УВ-насыщение или название скважины.
- Никогда не публиковать реальные документы и локальные пути из `data/`, текст геологических описаний, содержимое Excel и отчёты с такими данными.
- `.doc` является потенциально небезопасным бинарным форматом; сторонние распаковщики должны быть надёжно получены, проверены и включены в лицензирование. Не скачивать неизвестные бинарники.
- Excel: не портить исходный шаблон, не выполнять текст как формулу, не перезаписывать результаты по умолчанию, сначала временный файл и атомарная публикация.
- Выполнять `uv run ruff check .`, `uv run ruff format --check .`, `uv run ty check`, `uv run pytest` на поддерживаемых ОС.
- GitHub-репозиторий публичный. Перед `gh repo create` и push проверить `git ls-files`, `.gitignore`, отсутствие файлов из `data/` и секретов.
- Не использовать force push, удаления чужих репозиториев, переписывание истории Git и неподтверждённые лицензии.
- PEP 758 в Python 3.14: `except A, B:` — валидная конструкция.

- После КАЖДОГО содержательного Codex-промпта обязательный последний шаг:
  `uv run python scripts/handoff.py create`, затем
  `uv run python scripts/handoff.py verify --archive <созданный-архив>`.
  Даже при частичном результате/ошибках попытаться создать архив с truthful
  FAIL/BLOCKED/NOT_RUN/PENDING. Нельзя унаследовать старый PASS.
  Перед этим `uv run python -m scripts.attest --remote` фиксирует команды/tests/API;
  отсутствие evidence не является PASS. Правила и схема — docs/HANDOFF.md.
  В финальном ответе дать абсолютные локальные пути tar.xz и .sha256, ID, размер,
  create/verify status. Архив приватен: никогда не push/upload в GitHub.
  Нет автоматического hook окончания произвольного промпта: правило исполняет агент.
  Для GitHub-only операций без локальных изменений допускаются status и пакет по запросу.
- Production releases только через main workflow с общим queue:max slot;
  теги/опубликованные assets неизменяемы. PR/diagnostic не расходуют patch.
  Ручная визуальная приёмка Excel остаётся PENDING до подтверждения пользователя.
